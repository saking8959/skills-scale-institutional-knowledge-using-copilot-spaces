# OctoAcme Project Management Process Docs

## Overview

OctoAcme runs projects using a **customer-first, iterative delivery approach** with clear ownership and data-informed decisions. This directory contains the complete set of project management guidance, templates, and checklists used across all projects at OctoAcme.

### Core Principles
- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Key Roles at a Glance

See [Roles & Personas](octoacme-roles-and-personas.md) for full details:

- **Project Manager (PM)**: Coordinates delivery, schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, measures success
- **Developers**: Implement features, collaborate on design, ensure testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs and approvals

---

## Key Artifacts You'll Create

Across the OctoAcme project lifecycle, you'll maintain these key artifacts:

- **Project Charter / One-pager** — Business case and high-level overview
- **Risk Register** — Tracked issues, mitigation plans, and status
- **Project Board** — Backlog, In Progress, In Review, QA, Done columns
- **Release Plan & Milestones** — Timeline and key deliverables
- **Acceptance Criteria & Definition of Done** — Quality gates and completion standards
- **Retrospective Notes & Action Items** — Learnings and improvements

---

## Communication Cadence

- **Daily**: Team standups (15 min)
- **Weekly**: PM + PdM sync, delivery team standup, risk review
- **Bi-weekly or Monthly**: Stakeholder updates
- **Per Sprint/Milestone**: Demo/Review, Retrospective
- **Ad-hoc**: Escalations and incident communications
